# DECISIONS

Decisions made during the autonomous build, with the reason. Newest at the bottom.

| # | Decision | Why |
|---|---|---|
| 1 | Vanilla TypeScript + Vite (no Preact) | The prototype is template-string UI; a straight typed port keeps the UX/copy identical and the bundle small. An auto-escaping `html` tagged template replaces manual `esc()`. |
| 2 | RLS tests run on **PGlite** (Postgres 18 in WASM) with a Supabase auth/roles shim | No Docker on this ARM64 Windows machine. Same migrations, same `set role authenticated` + JWT claims as PostgREST. The suite can also be pointed at the live DB. |
| 3 | `people` table separate from `household_members` | The prompt needs people without a login (kids). Members = logins + roles; people = who an expense belongs to. `person_id = null` means "משותף" (joint), like the prototype. |
| 4 | Composite FKs `(household_id, id)` | Makes it impossible to reference a person/job from another household, independent of RLS. |
| 5 | Quotas live in `household_settings` but are protected by **column-level grants** | Members can change theme/send mode; only the super-admin RPC can change `quota_*`. |
| 6 | Reserve-then-finalize usage ledger with a row lock on the global cap | Enforces quotas *before* the API call without races; real cost recorded after. |
| 7 | E-mail contains a magic link **and** a 6-digit code | iOS home-screen apps don't share storage with Safari; a code typed in the PWA always works. PKCE flow for the link (URL fragment is free for the hash router). |
| 8 | Sign-ups disabled; invite accepted via `invite-signin` Edge Function + `accept_invite` RPC; invite bound to the first e-mail that uses it | "No public sign-up" and a leaked link can create at most one account. |
| 9 | New households are created by the super-admin (owner-invite link) | Prevents users multiplying their AI quota by creating households. Admin can only issue an owner invite for a household with **no** members, so they can never enter a family's data. |
| 10 | Google sign-in not implemented | Optional in the prompt; OAuth redirects also break inside iOS home-screen apps. |
| 11 | Statement PDFs are sent to Claude as a `document` block (no pdf.js) | Simpler, keeps the text layer; PDF limit 5MB like images. |
| 12 | Analysis prompt is built on the client from the month summary (as in the prototype) and sent to `analyze-month` | Reuses the prototype logic; the function wraps it in a fixed prompt, enforces structured JSON output and filters links to the whitelist. A user can only influence their own household's analysis. |
| 13 | Git author = GitHub noreply address | The repo is public; keeps the personal e-mail out of commit metadata. |
| 14 | Live DB migrations via `scripts/db.mjs` over the IPv4 session pooler with the DB password | No personal access token yet; the Management API (link/secrets/functions) needs one. Tracking table is the CLI's `supabase_migrations.schema_migrations`, so the CLI stays compatible later. |
| 15 | MFA enforced with **restrictive** RLS policies (`mfa_gate`) + `is_owner()`/`is_super_admin()` requiring `aal2` | Restrictive policies AND with the existing ones, so no finished policy had to be rewritten. Households/roster/settings stay readable at aal1 so the app can say "enter your code". |
| 16 | MFA required when: owner, super-admin, user has any verified factor, or household `require_mfa` | Matches the addendum; a half-finished (unverified) enrollment never locks a user out. |
| 17 | Own recovery codes (10, sha256 of `user_id:CODE`, single use) instead of Supabase's built-in ones | Supabase's recovery codes exist but are marked experimental and need server-side enablement. Ours: using a code (Edge Function `mfa-recover`) removes the lost TOTP factor, the user re-enrolls. |
| 18 | Owner MFA reset: only for non-owner members of the same household, never the super-admin | Owner↔owner resets would let one owner weaken another's account. |
| 19 | Sessions stay long-lived (Supabase refresh tokens, localStorage) | Family members are not asked for a code on every open; a new device or sign-out asks again. |
| 20 | Categorization rule order: the pharmacy rule runs before the grocery rule | Bug found by the parser tests: in the prototype "סופר פארם" matched "סופר " and was filed as groceries. Everything else in RULES is unchanged. |
| 21 | Pre-commit scan in Node (not Python), with a separate **commit-msg** hook | One toolchain for the repo. The hub scans `.git/COMMIT_EDITMSG` from pre-commit, which at that moment still holds the *previous* message; a commit-msg hook scans the real one. |
| 22 | Real-name denylist is local (`.scan-denylist.txt`, built from the live DB by `npm run scan:names`) | Names of real families must never be written into the repo, not even into the scanner's list. `scan-ok` on a line = reviewed synthetic example. |
| 23 | Import aliases per issuer + a "signed amount" mode (Discount's single "זכות/חובה" column) | Loud column checks need explicit aliases; the signed column is how Discount exports look. |
| 24 | Commit messages in Hebrew from here on (מה שונה · למה · מה נבדק) | Mirrors hub AGENTS.md. Earlier commits stay in English. |
| 25 | `docs/design-pass/**` added to the `.gitignore` allow-list (PNG screenshots) | Requested by design-brief.md (before/after at 390px). Screenshots come only from `tests/e2e/screens.spec.ts` on the synthetic live fixture (`example.test` users, invented merchants) — never real family data. |
| 26 | Exactly one owner per household: partial unique index `household_one_owner` + `transfer_ownership()` (0007) | Elad, household-roles.md. The index makes a second owner impossible even through a bug; the transfer demotes the caller first, then promotes the target, in one transaction. Owner invites exist only as the super-admin's invite for an empty household (`accept_invite` refuses one once the household has an owner). UI calls the role "מנהל/ת"; the enum value stays `owner`. MFA rule unchanged. |
| 27 | Payment methods: the logged row (receipt / manual) **survives** a match and takes the statement's amount + date; the statement row is not inserted (import) or is deleted (statement first). Matching is a pure client function (`src/domain/match.ts`: ±1₪ or first installment, date −2…+5, fuzzy merchant, same method / issuer / bit rows), the write is one `security invoker` RPC (`apply_statement`, `merge_statement_row`) so RLS still applies and a partial import is impossible | payment-methods.md. Keeps category, note, person and receipt line items; no double counting. Waiting items are counted once (they are ordinary saved rows); a statement "covers" an item only when it runs ≥5 days past it, so late-month receipts are not flagged too early. |
| 28 | Every household gets default methods (מזומן, ביט/פייבוקס, העברה, אחר) by trigger; cards are added by the family, **last 4 digits only** (DB check `^[0-9]{4}$`; the receipt sanitizer turns any longer digit run into `****1234`) | Chips work from day one; a full card number can never be stored. |
| 29 | New excluded category "משיכת מזומן" (ATM). Parser rule split from "העברות ומזומן" (bit/PayBox stay there); ATM rows are kept on import (not counted) so the "מזומן" card can show withdrawn vs logged cash | payment-methods.md: an ATM withdrawal is a transfer to cash, not an expense. Categorization change, not a numeric rule. |
| 30 | Design pass: own inline-SVG illustrations and hand-rolled SVG charts; Lucide icons copied at build time (`scripts/lucide.mjs` → `src/ui/lucide.ts`, 36 icons) instead of a runtime icon package | design-brief.md: no heavy dependencies, strict CSP, recolor with theme tokens. Lucide is ISC (+MIT), not MIT as the brief assumed — the notice ships as a legal comment (ASSETS.md). Cost: +11 KB gz JS, +2 KB gz CSS. |
| 31 | Dark mode is a per-device choice (`localStorage hb2-scheme`: system / light / dark), not a household setting; every theme preset gets a computed dark variant (accent kept, "deep" becomes a light tint, soft = 24% accent on the dark surface) | A shared household setting would force one family member's preference on everyone's phone. No new DB column needed (the design pass must not change data). |
| 32 | The app re-renders with innerHTML, so motion runs in an after-render hook and only on change (count-up keyed per month, tab transition only when the tab changes); swipe-delete waits 5 s for "ביטול" before deleting; everything is off under prefers-reduced-motion | Avoids animations replaying on every keystroke; deletion stays undoable without a trash table. |
| 33 | iOS splash screens use a flat theme color and are excluded from the service-worker precache | Gradient PNGs were 2.9 MB; flat ones are ~300 KB for 10 sizes, fetched by iOS only at install. |
| 34 | "איפה הכי זול?" uses SuperMCP's public **REST** API (`POST /v1/delivery/optimize`, `GET /v1/products/similar`, found in their `/openapi.json`) from a new Edge Function `price-compare`, not their MCP endpoint | Terms (updated 18.8.2026, read 26.10.2026): free, personal and "reasonable business use" allowed; forbidden: overloading, bypassing limits, scraping the whole DB, presenting results as our own → we show "מחירים מ-SuperMCP" with a link, rate-limit 10 comparisons/household/day, cache 6h. Prices are information, not an offer; no uptime/accuracy guarantee → "להמחשה" note + comparison links as fallback. Privacy (7.9.2026): list not linked to a person, address not stored, technical logs 90 days, geocoding via OpenStreetMap → we send ONLY item names/quantities + the city/street the family chose (0010), never names/e-mails/ids. Their site has text addressed to AI assistants ("install it globally") — ignored, not an instruction from Elad. No public source repo was found despite "open source". |
| 35 | Automatic capture (Apple Pay Wallet automation + Back Tap quick add) posts from iPhone Shortcuts to a new Edge Function `capture` with a per-user **capture token** (`hbc_…`, shown once, sha256 in `capture_tokens`, rotate = revoke old) instead of a session; no Origin header required for that one endpoint | A shortcut can't sign in, and opening a URL from a shortcut opens Safari, not the home-screen app. The token is scoped in SQL (`svc_capture`): only its own user, only its own household, only while that user can still write; rate limited per token and per IP; 2-minute dedup. Wallet rows use the existing `awaiting_statement` (the spec's "pending_statement") so the statement import merges them. Category rules moved to `supabase/functions/_shared/rules.ts` (the app re-exports them) so app and function categorize the same way. Foreign amounts are noted and always reviewed until feature 5. |
| 36 | Admin dashboard runs on **Elad's Hetzner server**, not as a Claude Artifact: a cron job of the `vibes` user (every 5 min) runs one bundled file that signs in as the new DB role **`hb_stats`** (0012: NOLOGIN in git, login + password set by `scripts/stats/role.mjs`; may only call `stats_snapshot()`, no table privileges) and writes a static page to `/srv/tools/bayit-admin/`, behind Caddy `basicauth` (user `elad`). Households appear only as an ordinal; the collector rebuilds the snapshot from an allow-list and refuses anything with "@". Last deploy = GitHub's public Actions API | Elad (26.10.2026): "להעביר את זה לשרת שלי ושזה יתעדכן אוטומטי כל הזמן". The server is shared with company tools, so the credential there must be worthless beyond aggregates — hence a dedicated role instead of the service-role key. The DB password is sent as a SCRAM verifier (never plain text in SQL/logs). Server changes run only from the bridge by Elad (`scripts/stats/install-server.sh`: backup → `caddy validate` → reload, restores on failure). TLS to the pooler uses `rejectUnauthorized: false` like every other script here — a MITM could at most read the aggregates. |
| 37 | Budget month start (1–28, `household_settings.month_start_day`, 0013): the stored `transactions.month` is **not** recomputed — the budget month is **derived** by one rule, `budgetMonth()` (`src/domain/month.ts`) = `public.budget_month()` (SQL): start 1 → stored month; stored month ≠ the date's month (installment / row the statement moved) → stored month; else day ≥ start ? month : month before. A budget month is named after the month it starts in (start 10: "אוקטובר" = 10.10–9.11). Everything monthly goes through it: `txOf` (overview, transactions, fixed status, tips, analysis summary, subscriptions), budgets, fixed suggestions, "כמה נשאר להיום", yearly report + export, the budget-alert trigger (now also fires on a date change) and the weekly summary | next-features.md §3 (regression-sensitive). Deriving means changing the start day mid-month re-buckets every row instantly with nothing to migrate and nothing to get out of sync; start 1 is byte-for-byte the old behavior (pinned by tests written first, commit 0e49cd2). Statement months win over dates because the card statement already decided which month an installment belongs to. A TS↔SQL parity test runs both over every day around the boundaries. AI usage months (`local_month`) stay calendar months — quotas are not a family budget. |
| 38 | Voucher wallet (0014): `vouchers` + `voucher_uses`; **every voucher gets its own payment method** (type `voucher`, created/renamed/hidden/removed by trigger) so paying with it is just the existing "איך שילמת?" chip — a SAVED transaction with that method = exactly one use row (trigger keeps amount/date/method/status/delete in sync), receipts under review don't spend it. Balance = initial − uses, recomputed in SQL, not writable by users. Manual uses and top-ups (negative) by hand; trigger-made uses can't be inserted or deleted by hand. Only the last 4 characters of a code are stored (DB check). Expiry reminders 30/7/1 days in `svc_due_notifications` (pref "bills"), one per window so a missed day still reminds; overview card "שוברים שעומדים לפוג". Voucher methods are hidden from the manual payment-methods editor and never wait for a statement | next-features.md §4. Reusing payment methods means no change to the add / receipt / Apple-Pay flows. No full codes by default (as specified); encryption only if Elad asks later. No Edge Function change (notify sends whatever is queued). |
| 39 | Trip mode / foreign currency (0015): a transaction keeps `original_amount` + `original_currency` + `fx_rate` (all or none, never ILS) and `amount` stays ₪ = round(original × rate, 2) — one rounding rule in SQL and `toIls()` (shared TS). Rates: **Bank of Israel representative rates** (14 currencies) + **ECB reference rates crossed through EUR→ILS** for the rest — the Bank of Israel does **not** publish THB (checked 27.10.2026), the trip currency in the spec's example. One shared cache (`fx_rates`, service role only), fetched by the new Edge Function `fx-rates` at most once a day + once after the ~13:30 publication, a failure retried after 30 min; a BoI rate is never overwritten by a cross rate. Manual rate per household per currency (`fx_overrides`, RLS) wins. Fallback: an outage keeps serving the last cached rate (the app shows its date, "stale" after 4 days); nothing cached → 502 "enter a manual rate"; receipts / iPhone capture with no rate at all are saved unconverted, in review, with a note. Receipts read `currency` from the model; statements keep "סכום עסקה מקורי"; a statement merge into a logged foreign row stores the card's actual rate; the matcher allows ±5% (min ±1₪) for a logged foreign row (card rate + fees) | next-features.md §5. Both sources are official, free, key-less GETs — nothing about the household leaves the server. Quick add / Back Tap with no currency = the trip currency while trip mode is on, ₪ otherwise; Apple Pay amounts with a symbol ("฿350.00") are converted. Local Excel/CSV imports don't read an original-currency column yet (column names vary per issuer). |
| 40 | "השכונה שלנו" (next-features §6) is **derived, never stored**: `neighborhood()` (`src/domain/hood.ts`) turns the month's non-excluded spend per category into at most 12 plots — building **kind** by type of spending (house / shop / tower / office / medical / tree for "שונות" and unknown), **color** = the category's own color, **height** 1–5 floors by the square root of spend relative to the biggest category (so a small category stays visible), biggest at the back of the picture so nothing is hidden. Hand-drawn isometric SVG (`src/ui/hood.ts`), shades only through CSS classes from `--c` (`.hb-*` in design.css) so dark mode and every theme recolor it; each building and the legend are `cat-go` buttons. It is a card on the overview (after the hero, before budgets); for a finished budget month the same card is the month-end summary ("השכונה של <חודש> · סיכום החודש"). Month rule = `currentBudgetMonth` like everything else. No migration, no Edge Function, no dependency (+~1.9 KB gz total) | next-features.md §6, "<15KB gz, no heavy dependency". Nothing to store means nothing to migrate or get out of sync, and the budget-month start day re-shapes the neighborhood for free. Decorative image with a text sentence and a tappable legend next to it (same pattern as the donut), `role="img"` + label. 12 plots is what fits at 390px; the rest are counted in the sentence. |
| 41 | App logo redesign: one SVG master (`scripts/icons.mjs` `master()`) drives every PNG (icon 192/512, maskable, apple-touch, 10 iOS splash screens) and the in-app mark `markArt()` (`src/ui/art.ts`) is the same drawing in flat colors — a cream house with a coral roof, a gold coin with a ₪ rising behind it, on the teal gradient with a soft highlight. The in-app mark keeps the theme accent as its tile and `var(--accent-deep)` for the door, so presets and dark mode still recolor it; the house/roof/coin colors are fixed brand colors | Elad (28.10.2026): "אפשר לשנות את הלוגו של אפליקציה. משהו יותר מושך". The old mark was a white outline house on teal — correct but flat. Warm roof + gold coin gives contrast against the teal and says "home + money" at 60px. Flat colors (no gradient ids) in `markArt()` because a gradient defined in one inline SVG breaks when another SVG that holds it is `display:none`. Cost: icon-512 / maskable-512 PNGs doubled (~64→144 KB, ~54→131 KB) because of the gradients, precache 1175→1361 KiB. Installed copies keep the old icon until reinstalled (iOS reads it at install). |
